# CC-10 shared artifact storage

## Current acceptance result

The synthetic acceptance criteria passed on 2026-09-09.
Worker host A staged and published an artifact through the production artifact adapter.
Worker host B read the artifact through the same adapter and verified identical bytes and database metadata.
The hosts used separate Docker daemons and retained private runtime configuration.
The test shared only the existing artifact directory. It did not copy artifact bytes between hosts.

The [machine result](CC-10-worker-publication-result.json) records identity comparisons, checksums, public images, topology limits, and cleanup.
The shared-mode fault suite supplies partial-write, unavailable-storage, permission, interruption, and concurrency evidence.
The [cross-host procedure](../storage/cross-host.md) documents repeatable execution and Kubernetes prerequisites.

Both worker hosts ran on one physical Docker host with shared POSIX backing.
This result does not qualify NFS, separate physical failure domains, or district storage durability.
Those deployment-specific checks remain operator responsibilities. They do not change the completed synthetic ticket criteria.
